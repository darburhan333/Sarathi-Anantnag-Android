V11.47.0 — 24 October 2026
BASE: V11.46.0 STANDALONE NAVIGATION ERROR ALERT FIX, verified against BUILD_INFO hashes.

ADDED
- Read-only Telegram /status, /today and /help receiver using existing bot.
- Opt-in receiver checkbox and last check/reply/error indicators in popup and monitor.
- Fresh owned-tab health ping and loop-progress evaluation; no page mutation or reinjection
  from Telegram commands. Re-read state after ping to avoid mixing monitoring sessions.
- Primary private chat/sender authorization; groups, bots and other users rejected.
- Bounded long polling, one in-flight receiver, persistent update offset, stale-command
  filtering, coalesced replies, timeouts and credential-redacted error messages.
- Configuration changes invalidate pending responses. Webhook/other-receiver conflicts
  are reported; no webhook is automatically removed.
- Session Proceed-click count and last recorded Proceed-click timestamp, persisted locally.

FIXED / CLARIFIED
- V11.46 monitor badge said STOPPED during manual-OTP receipt watching. It now explicitly
  says MANUAL OTP or WATCHING and identifies the paused COV loop.
- Misleading hidden-primary-ID help text removed.
- Status report explicitly separates recorded attempts from bookings, and daily count
  (existing PC-local 9–21 window) from the new session count.

UNCHANGED
- Booking and COV decisions, timeouts and locking are not redesigned.
- content.js changes are the version log and metadata recorded at its existing count point.
- background.js adds only the status-module import. Existing failure handlers stay intact.
- booking-rules.js, audio.js, audio.html and icon.png are byte-identical to V11.46.
- Primary Telegram recipient and optional second alert recipient remain unchanged.

LIMITS
One command receiver per bot; no multi-profile aggregation. PC must stay awake and online.
No remote START/STOP or booking. No real-world delivery/Win7/Chrome109 tests in this build.
No guarantee all V11.46 defects are eliminated. Known V11.46 limitations remain, including
manual review after exhausted eligible-date scans and no automatic retry of failed alerts.
