MPARIVAHAN ANANTNAG V11.41 QUOTA ALERT AND DATE GUARD FIX
Base: V11.40.0. Continues V11.34.1 lineage; no older rebuild.

USER EXCEPTION
The existing hard-coded primary Telegram recipient (7930718570), fallback,
settings fields and optional second recipient are intentionally unchanged.

FIXES
1. Quota alerts now use quotaOptions(), the same verified table parser used by
   assisted booking. LMV, MCWG and BOTH_AVAILABLE can actually fire. Zero or
   ambiguous mappings, missing dates, stale sessions and conflicting tracked
   dates cannot generate a positive-quota alert. Per-session deduplication is
   retained; quota messages do not wait for Telegram before booking can proceed.
   The counts represent the highest verified option per class, not a sum of
   shared counts. BOTH_AVAILABLE describes availability of both classes on the
   displayed quota page; it is not a booking-success message.
2. Booking requires a valid, unique Available Time Slots date matching the
   selected date. Missing date waits for loading (up to the existing 9-second
   quota window), then pauses for manual review. Invalid/conflicting labelled
   dates are rejected. A fresh date check is required immediately before click.
3. A booking reservation carries a unique token and originating session/document.
   A known pre-click abort releases only that reservation, including after STOP.
   A dispatched click, throwing click or uncertain outcome keeps the lock. There
   is no automatic retry after a click. Manual-review pauses stay paused; fixing
   the page and deliberately re-enabling assisted booking is still required.
4. Replaced separate 1.6/1.8/2.2-second inspection timers with one non-overlapping
   1.1-second inspection scheduler. Brief page-text caching avoids duplicate
   reads; mutations invalidate it and critical date checks always read fresh text.
5. Version labels/log prefix/README now reference V11.41. Removed unused POLL_MS.
   A neutral injection guard is used; the legacy sentinel is retained solely to
   avoid duplicate scripts when an old page has not yet been refreshed.
6. Notifications retain best-effort 20-second dismissal, with a one-minute Chrome
   alarm fallback for service-worker suspension. Timing can be delayed by sleep;
   this does not promise exact dismissal or persistence across browser restart.
7. Removed redundant activeTab, broad tabs and the unnecessary windows manifest
   entry. Kept scripting for injection/recovery and existing narrow host access.
8. Verified quota tables count all their radios before row parsing so malformed
   rows cannot silently disappear from the mapping-completeness check.

PRESERVED
8-second minimum pre-Proceed wait; displayed month only; green Wednesday/Thursday
scan; LMV+MCWG preference; single-class fallback; quota >=1; manual OTP and final
confirmation; two Telegram recipients; desktop/sound alerts; separate monitor;
seven-stage tracker; STOP/restart and ownership synchronization fixes.

TESTING
All packaged JavaScript syntax checks and these 10 offline Node test suites pass:
audit_140.js, calendar_rules.js, fixes_141.js, proceed_140.js, quota_dom_140.js,
regression.js, restart_139.js, status_139.js, synthetic_301.js, ui_140.js.
The new suite connects the production quota parser to content alert generation
and the actual background handler with mocked browser APIs. It covers all three
quota alert kinds, dedup, invalid/missing dates, pre-click cancellation, retained
uncertain locks, token/document isolation and notification alarm cleanup.
The 301 test counts simulated monitoring attempts, not real bookings.

LIMITATIONS
No live Sarathi booking, live Telegram delivery, full browser end-to-end run or
physical Chrome109/Windows7 audio test was performed. Chrome109 audio fallback
remains fixture-tested, not real-device certified. Permissions and monitor-window
behaviour also need confirmation in the installed browser. Previous release notes,
archived evidence and the optional browser harness are historical/reference files.

UPGRADE
Stop monitoring. Back up the existing folder. Replace its contents with this ZIP,
keeping manifest.json at the folder root. Reload at chrome://extensions, then
refresh every Sarathi tab to replace old content scripts. Close/reopen the monitor.
Verify version 11.41.0 and use TEST ALERTS before starting. Do not run two copies.
