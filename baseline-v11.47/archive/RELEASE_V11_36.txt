MPARIVAHAN ANANTNAG V11.36.0 — CONSOLIDATED RECOVERY & BOOKING SAFETY
====================================================================
BASE: MPARIVAHAN ANANTNAG V11.35.0 CONSOLIDATED STABILITY ACCESS FIX
Original V11.34.1 remains unchanged. This release includes both prior V11.35
fixes and further corrections. Chrome Manifest V3, Chrome 109 or later.

PRIMARY BUG TARGET: After ~30–40 minutes the attempt counter stopped while the
normal LMV/MCWG page stayed open and the monitor displayed Delayed / checking.
There is NO 200- or 300-attempt cap in the source.

NEW IN V11.36
- Health alarm checks actual COV loop activity/progress every minute even if
  heartbeats are still fresh (corrects V11.35's main recovery blind spot).
- A stale COV loop can be invalidated by generation number and restarted; an
  older waiting loop cannot subsequently submit another PROCEED.
- Action authorization in background checks owner tab, new session ID, running
  state, calendar lock and current booking mode before critical page clicks.
- Background serializes action approvals and persists BOOK SLOT single-submit
  reservation before authorizing one click; recovery cannot reset the lock.
- Starting a NEW session after an uncertain BOOK SLOT submission now shows a
  manual confirmation instead of silently unlocking it.
- Popup text work only runs when the actual popup Back button is visible;
  supports modal text inside or outside the dialog. Reduced timer/DOM overhead.
- Quota-page analysis waits for stable options up to 9 seconds instead of
  declaring failure as soon as controls render. Positive availability must
  match its vehicle-class radio in the same row AND a correctly labeled
  availability/quota table column. Ambiguous data means MANUAL REVIEW.
- Real calendar includes both previous/next month page URLs; rejects dates
  older than today and invalid day/month combinations.
- SMS detection requires verification inputs, not a bare URL; avoids wrongly
  stopping monitoring when a different step reuses a familiar path.
- SMS alerts are scoped by monitoring session. Calendar dedup includes visible
  green-day signature so new dates aren't always suppressed.
- Alerts are serialized separately from critical action gates, so waiting on
  Telegram does not delay booking authorization.
- Sound START/STOP race guard prevents old playback from recreating alarm.
- Monitor displays a distinct stalled-loop/recovering state and updates
  assisted-booking checkbox when actual stored state changes.
- Fixes initial monitor refresh race; monitor status updates use storage events.
- Better preserved error states and narrowed popup Back targeting from V11.35.
- Keeps 8-second minimum pre-submission countdown, LMV/MCWG selection, monitor
  window, optional Wed/Thu assistance, manual OTP, history, Telegram to two
  recipients, sound, desktop alerts and seven-stage tracker.

LIMITATIONS / NOT YET CONFIRMED
- Actual Sarathi quota table structure is not fully preserved by the archived
  diagnostic JSON. If it lacks an unambiguous availability-column heading the
  assisted booking stops for manual review instead of guessing quota from S.No.
- Calendar link/onclick variations, SMS form markup, receipt table variants and
  full end-to-end BOOK SLOT flow require live website validation.
- No live Sarathi login, slot booking, Telegram API or one-hour browser/CPU
  stress test was performed here. Chrome may suspend or throttle background
  pages. Windows sleep cannot be bypassed by an extension.
- "Access requested" requires the user to grant extension Site access in Chrome.
  A ZIP cannot grant itself permission or bypass Chrome's site-access controls.
- An 8-second minimum wait does not guarantee 8 seconds click-to-click; the
  Sarathi website controls the response time.

INSTALL / UPGRADE
1. Keep a safe backup of your existing V11.34.1/V11.35 folder and ZIP.
2. In chrome://extensions disable the old extension before updating.
3. To retain the same unpacked extension identity and stored settings, update
   the files in the same original extracted extension folder (same path) and
   click Reload. A newly extracted folder at another path can have a new
   extension ID and may not inherit Telegram settings/history.
4. On the Sarathi extension details page, set Site access to
   "On sarathi.parivahan.gov.in"; do not use "On click" for monitoring.
5. Re-enable, open Sarathi, click START, and first test at least one normal
   no-slots cycle, then test long-run monitoring beyond 300 attempts.
6. When calendar appears, ensure assisted booking is deliberately enabled if
   desired. OTP/CAPTCHA entry and final verification stay MANUAL.
7. If monitoring stalls, take a screenshot of Sarathi and the monitor, record
   attempt number, CPU/RAM load and Chrome version. Do not disclose OTP or
   applicant identifiers in screenshots.
