V11.35 LONG-RUN STABILITY / ACCESS AND PROCESSING FIX
Base: V11.34.1 MONITOR SYNC FIX. Original preserved.

Focused changes:
- Only selected Sarathi tab can run monitoring, inspect calendar or book. Other Sarathi tabs remain inert.
- Running flag cached in content script; removes frequent storage reads in 200ms waits.
- Heartbeats limited to owned tab; reduce writes to once per five seconds.
- Debounce DOM observer to at most one inspection per 500ms, ignoring noisy attribute mutations.
- Background health check pings actual content, recovers a stopped COV loop or reattaches a missing script where site access permits.
- Permission/reconnect failures report explicit Site access/connection status; no automatic permission override.
- Restrict popup Back fallback to actual dialog.
- Preserve specific stop/error status when running becomes false.
- Reset SMS deduplication on a fresh manual START.
- Fix false sound-test OK results.
- Strictly reject impossible calendar dates in shared booking rules and live calendar candidates.

Unchanged design: eight-second retry; original COV selection, optional assisted booking, guarded BOOK SLOT, manual OTP, Telegram, alarms, monitor window, seven-stage tracker, quotas, success detection.

LIMITATIONS: Chrome may throttle or suspend tabs in background; alarms/recovery cannot guarantee continuous 8-second execution while Chrome is suspended or the PC sleeps. Live Sarathi and Telegram tests were NOT run. Existing settings in chrome.storage.local remain on update provided extension ID is preserved. Always test on a logged-in site with Site access set to On sarathi.parivahan.gov.in.
