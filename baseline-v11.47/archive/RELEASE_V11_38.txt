MPARIVAHAN ANANTNAG V11.38 — INTEGRATED BOOKING-TO-SMS TEST
============================================================
BASE: V11.37 CALENDAR AUTOMATION FIX (which includes V11.36 stability fixes).
UNCHANGED BASE BACKUPS: V11.34.1 / V11.35 / V11.36 / V11.37 ZIPs.

IMPORTANT: This build is for one end-to-end LIVE USER TEST when an authorized
Sarathi session reaches a booking calendar. Automatic selection and BOOK SLOT
submission operate only when assisted calendar booking is explicitly enabled.
No CAPTCHA or OTP bypass, no automatic SMS entry or final confirmation.

WHAT IS NEW IN V11.38:
1. Uses original V7 deep diagnostic evidence, not just archived-evidence.json.
   Verified zero-quota table structure on /slots/fetchdlslotdetinfo.do:
      HEADER: [Time Slots] [LMV, MCWG]
      ROW:    [09.00-18.00] [radio(name='LMV, MCWG') + span('0')]
   The user's December 2026 photograph shows the same cell with '13'.
2. Reads a numeric quota ONLY when inside the actual time-slot row, below a
   matching COV column heading, and in the same cell as the associated radio.
   Numeric radio IDs and unrelated page numbers NEVER count as quota.
   Where an Available Quota legend is present, it must match that section.
   Retains the older independently verified availability-column fallback.
3. Disabled radio with verified zero count is treated as unavailable; checks
   next eligible green Wed/Thu date. Disabled positive radio remains ambiguous
   and requires manual review (never clicks it).
4. Compares the explicit 'Available Time Slots DD-MM-YYYY' label, when present,
   with the date previously selected in the calendar. Stops on a mismatch.
5. Waits up to 3 seconds after selecting a positive radio for BOOK SLOT to
   become enabled; uses V11.36 background single-submit authorization.
6. Sends a manual-review warning through existing desktop/Telegram pipelines
   when the quota/date controls cannot be verified, instead of silently stopping.
7. Keeps monitoring interval (8 seconds), background recovery, status UI,
   two Telegram recipients, calendar alarms, seven-stage tracker and manual OTP.

TESTS PERFORMED OFFLINE:
- node --check on all 5 JS files: PASS.
- node tests/regression.js: PASS (owner/tab gating, STOP, single BOOK SLOT,
  recovery from stalled loop, valid dates, sound race).
- python tests/browser_full_flow.py: PASS (headless Chromium DOM simulation):

  This test simulates navigation in-place with an offline DOM. NO real website

- ZIP integrity / JSON manifest validity: PASS.

IMPORTANT LIMITATIONS:
- The V7 deep diagnostic proves the radio+span table shape with a ZERO count,
  and the user's photograph shows 13 in the matching visual position. Whether
  the live site still uses the identical DOM for positive quotas needs a live
  attempt to verify. We did not access the real website or account.
- Actual background Chrome CPU throttling, live slot availability, Telegram
  delivery and OTP-stage markup require user testing on the real site.
- Green-date automation prioritizes future Wednesdays and Thursdays only;
  there is no fallback to other weekdays in this release.
- Assisted booking is deliberately OFF by default; enable the monitor setting.
- Chrome Site access must be explicitly granted by the user.

INSTALL / UPGRADE:
1. Back up the original V11.37 folder and ZIP.
2. Disable prior extension version; extract this ZIP into the SAME unpacked
   extension folder path if you want to keep extension identity/settings.
3. In chrome://extensions click Reload and confirm extension version 11.38.0.
4. Set Site access to 'On sarathi.parivahan.gov.in' (not 'On click').
5. In the monitor, enable assisted calendar booking and click START.
6. When calendar appears, do NOT click dates immediately: observe the monitor
   stages for selection, quota verification and one BOOK SLOT click.
7. If SMS/OTP screen appears, the extension stops; enter SMS code manually.
8. If it stops for manual review, capture monitor status and a screenshot of
   the date/quota area WITHOUT applicant identifiers or OTP codes.
